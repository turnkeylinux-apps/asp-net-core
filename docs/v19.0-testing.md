# ASP.NET Core v19 acceptance

## Dependency decision

The appliance uses Microsoft's Debian 13 repository for .NET 10 LTS, which is
supported on Debian 13 through November 2028. The build verifies Microsoft feed
2025 key fingerprint `AA86F75E427A19DD33346403EE4D7792F748182B` and
SHA-256 `d45224d594d969f084232deaaf97c58ca502a9d964c362d7aaef5a76e16b3dd1`.
Microsoft documents `https://packages.microsoft.com/keys/microsoft-2025.asc`
for repositories created after April 2025, including Debian 13. The previous
candidate used `microsoft.asc`, fingerprint
`BC528686B50D79E339D3721CEB3E94ADBE1229CF`; a disposable Debian 13 probe
rejected that key because the repository now requires key ID
`EE4D7792F748182B`.

The example uses EF Core 9.0.19 and stable Pomelo 9.0.0 with a retained NuGet
lock file. Pomelo is the provider that supports this appliance's MariaDB
database. No stable EF Core 10 Pomelo provider is available yet, so the two
packages remain on their mutually compatible stable 9 line. Debian packages
are preferred and supply Nginx 1.26.3-3+deb13u7 and MariaDB
1:11.8.6-0+deb13u1. The Microsoft feed is the documented upstream exception
for .NET 10 LTS, which Debian 13 does not provide. The locked official NuGet
packages are the upstream exception for the sample's EF and MariaDB provider.

## Failure-boundary evidence

The focused pre-rerun probes established three product boundaries:

- A deliberately mismatched Nginx certificate/key reproduced startup status
  1; restoring the pair and restarting Nginx produced a 302 HTTPS redirect:
  `nginx_tls_race_probe=PASS mismatch_status=1 paired_restart=PASS redirect=302|https://localhost/`.
- A probe against the shared MariaDB helper reproduced its activating-state
  race. Before the fix it self-started and then stopped MariaDB; after an
  explicit `systemctl start mariadb.service`, the helper observed the active
  service and did not stop it: `mysqlconf_activation_race_probe=PASS`.
- A 1,950,000-byte real `apt-cache policy` stream reproduced the updater's
  pipe status 141 when an early-exiting reader was used. Reading the complete
  output made both pipeline elements exit 0:
  `real_apt_cache_sigpipe=PASS package=bash bytes=1950000 old_pipe=141,0 fixed_pipe=0,0`.

An exact disposable Trixie updater probe then passed with the installed SDK,
runtime, EF, and Pomelo versions above before the final appliance run.

## Deferred issues

- NuGet package upgrades remain supervised because provider and EF Core
  versions must stay compatible with the sample source.
- Pomelo has not released an EF Core 10 provider. Move both packages to the
  stable 10 line when it is available and passes MariaDB acceptance.
- The example demonstrates database reads and persistence. It is not an
  authentication or administration product.
- Docker acceptance does not repeat installer, kernel, or hardware checks.
- The Docker kernel rejects the appliance hostname firstboot call and the
  `systemd-sysctl` unit. These inherited container limitations do not affect
  the explicitly tested application services.
- Restarting ASP.NET can expose a brief proxy 502 while Kestrel starts. The
  supervised restart test retries through that bounded window and passed.
